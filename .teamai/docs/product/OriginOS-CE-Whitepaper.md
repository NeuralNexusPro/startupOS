# OriginOS CE 产品说明白皮书

**版本**：1.0  
**日期**：2026-07-15  
**产品**：OriginOS CE

---

## 摘要

OriginOS CE 是一个 AI Native 工作系统。它将项目、角色 Agent、技能、文件、通知、定时任务和本地记忆组织在同一个桌面工作台中，让用户不再只是在聊天框里向 AI 提问，而是能够把 AI 配置成可持续工作的角色、可复用的技能和可被时间/事件唤起的系统能力。

OriginOS CE 当前以 Next.js Web 应用和 Electron 桌面应用两种形态运行。Web 负责交互体验，Electron 主进程负责本地系统能力：原生通知、后台调度、跨窗体通信、可写数据目录、日志、打包与自动更新。

## 1. 产品背景

过去一轮 AI 工具主要围绕“对话”展开：用户打开聊天框，输入问题，获得一次回答。这种模式适合即时问答，但不适合承载长期工作，因为它缺少三个关键能力：

1. **持久上下文**：工作目录、项目文件、角色记忆和历史经验无法自然沉淀。
2. **系统行动力**：AI 很难主动在正确时间唤起用户或执行任务。
3. **可组合能力**：一次性的提示词无法形成可复用的技能、角色和工作流。

OriginOS CE 的设计目标是把 AI 从“问答工具”推进为“本地工作系统”：它不是替代操作系统内核，而是在现有桌面环境之上提供 Agent 原生的工作组织方式。

## 2. 产品愿景

OriginOS CE 的愿景是成为个人 AI 工作空间的基础设施。用户可以在其中创建角色、安装技能、组织项目、上传文件、安排定时任务，并让系统在合适的时间通过通知或窗口主动唤起对应能力。

核心原则：

- **Agent 不是一次性会话，而是工作主体**：每个 Agent 都应有身份、工具、工作目录和记忆。
- **技能不是提示词片段，而是可复用能力单元**：技能可以被首页、项目、Agent 或定时任务调用。
- **通知不是消息展示，而是行动入口**：通知点击应能打开项目、角色、Agent 或技能，并携带初始指令。
- **定时任务不是提醒事项，而是系统能力调度器**：时间可以触发 Agent、Skill、系统通知或系统工具。
- **数据本地优先**：项目、Agent、Skill、记忆、实践日志和产物都以文件形式存储。

## 3. 产品能力版图

### 3.1 首页工作台

首页是 OriginOS CE 的主入口。用户可以从首页启动创建 Agent、创建角色、打开技能市场、进入工作区、运行头脑风暴或工作流构建等能力。

首页应用采用配置驱动，支持两类入口：

- **Action 入口**：打开工作区、创建 Agent 等系统动作。
- **Skill 入口**：打开指定技能窗口，进入专项能力会话。

### 3.2 Agent 系统

OriginOS CE 支持多种 Agent 形态：

- **通用 Agent**：执行一次或多轮任务，支持工具调用和流式响应。
- **RoleAgent**：拥有角色定义、状态机、工具箱、记忆、知识和经验模式。
- **Project Agent**：运行在项目上下文中，读取项目文件并沉淀项目产物。
- **多 Agent 协作运行时**：支持 supervisor、worker、blackboard、事件流和拓扑视图等协作基础设施。

Agent 的工作目录中通常包含：

- `Agent.md`：身份定义
- `Role.md`：角色状态机
- `Tool.md`：可用工具声明
- `Taste.md`：风格指南
- `Memory.md`：历史记忆
- `Knowledge.md`：知识快照
- `Patterns.md`：经验模式

### 3.3 Skill 系统

Skill 是 OriginOS CE 的能力单元。它可以来自系统内置、项目目录或用户目录，可以从首页入口、项目、Agent 或定时任务中启动。

Skill 系统支持：

- 技能内容读取
- 技能窗口会话
- 附件上传
- 技能市场搜索与安装
- 技能产物写入可写数据目录
- 由 Agent 调用技能

### 3.4 项目系统

项目是长期工作的组织单元。OriginOS CE 将项目元数据、项目文件、访谈产物、业务模型、方案文档和项目 Agent 上下文组织在同一个项目目录下。

典型项目流程：

1. 创建或初始化项目。
2. 通过项目 Agent 或访谈模块收集业务信息。
3. 生成业务模型、方案或工作文档。
4. 在工作区中查看和编辑文件。
5. 由 Agent/Skill 继续补充、分析和改写产物。

### 3.5 定时任务系统

定时任务是 OriginOS CE 的系统级调度能力。用户可以创建任务，并指定触发时间与执行动作。

支持的时间模式：

- 一次性时间
- 固定间隔
- Cron 表达式

支持的动作：

- 启动角色/Agent
- 启动 Skill
- 发送系统通知
- 调用系统工具

在桌面端，定时任务由 Electron 主进程后台调度。应用启动后会立即扫描一次到期任务，之后每 30 秒扫描一次。任务运行结果会写入运行记录。

### 3.6 通知系统

OriginOS CE 同时提供应用内通知和操作系统通知。

应用内通知：

- 小铃铛展示未读数量。
- 通知面板展示列表、状态和时间。
- 通知可标记已读或关闭。
- 点击通知可触发关联动作。

操作系统通知：

- Electron 主进程调用原生 Notification。
- 支持 macOS 和 Windows 的系统级通知通道。
- 通知点击可唤起项目、Agent、RoleAgent 或 Skill。
- 通知动作可携带初始指令。

通知在 OriginOS CE 中不是简单的消息展示，而是系统行动入口。

### 3.7 工作区与文件能力

工作区提供项目文件管理和 Markdown 编辑能力。Agent 工具系统提供文件读写、目录操作、文档解析、表格读取等能力。

文件能力遵循边界原则：

- 工具只能在授权工作目录内操作。
- 打包态写入 Electron userData 数据目录。
- 不写入应用资源目录、DMG 或 asar 只读路径。

### 3.8 认知沉淀

OriginOS CE 的长期目标不是只完成任务，而是积累经验。当前系统已经具备认知沉淀的基础结构：

- 实践日志记录 Agent 行为与结果。
- Memory.md 存储历史记忆。
- Knowledge.md 存储知识快照。
- Patterns.md 存储最佳实践、反模式和反思记录。
- Agent 启动时加载快照，运行中保持上下文稳定。

Pattern 总结由 Agent/LLM 基于实践样本完成，而不是用代码正则或字符串截取生成正文。

## 4. 典型场景

### 场景一：创建一个角色 Agent

用户从首页点击“创建角色”，进入角色创建技能。系统通过对话引导用户定义角色身份、行为风格和工具箱，最终在本地数据目录生成角色 Agent 工作目录。之后用户可以从首页或通知中再次唤起该角色。

### 场景二：安装并运行一个技能

用户打开技能市场，搜索并安装技能。安装后技能可作为首页入口、Agent 工具箱能力或定时任务动作被调用。技能运行过程中的附件和产物写入可写数据目录。

### 场景三：定时启动一个技能

用户打开右上角定时任务面板，新建任务：

- 时间：每天 9 点
- 动作：启动某个技能
- 初始指令：生成今日工作计划

到点后桌面主进程执行任务，并通过系统通知提醒用户。用户点击通知后，OriginOS CE 打开对应技能窗口并发送初始指令。

### 场景四：系统通知唤起项目

定时任务或 Agent 产生通知，通知中包含项目 activation target。用户点击系统通知后，桌面端恢复窗口并打开对应项目，可选地自动发送一条初始指令。

### 场景五：项目内沉淀方案

用户创建项目后，通过项目 Agent 收集需求、读取附件、生成业务模型和方案文档。相关产物保存在项目目录，后续可由工作区编辑，也可继续交给 Agent 改写。

## 6. 数据与部署

OriginOS CE 使用本地文件系统作为主要数据层。

开发态通常使用仓库内 `data/`。桌面打包态使用 Electron userData：

- macOS：`~/Library/Application Support/@originos/desktop/data`
- Windows：`%APPDATA%/@originos/desktop/data`

桌面端支持：

- macOS DMG / ZIP
- Windows NSIS installer / ZIP
- electron-updater 自动更新
- 七牛 CDN 发布更新元数据和产物

## 7. 安全与边界

OriginOS CE 当前采用本地优先与工具边界控制：

- 工具执行必须受工作目录限制。
- Agent 只能调用其工具箱允许的工具。
- 打包态不写只读资源目录。
- 系统通知点击只触发受控 activation target。
- 自动更新包需要签名和完整性校验。

## 9. 后续方向

OriginOS CE 后续会沿三个方向继续演进：

1. **更稳定的系统能力**：定时任务、系统通知、自动更新和跨平台打包持续自动化验证。
2. **更强的 Agent 工作资产**：Memory、Knowledge、Patterns 的查看、编辑、版本化和复用。
3. **更自然的工作流编排**：将项目、角色、技能、通知和时间调度组合成可视化或对话式工作流。

OriginOS CE 的最终目标，是让 AI 能力不再停留在一次性对话，而成为可被组织、唤起、沉淀和演化的个人工作系统。
