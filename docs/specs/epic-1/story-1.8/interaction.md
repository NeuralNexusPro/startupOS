# Story 1.8 交互设计

## 流程

访谈识别活动 → 保存草稿 → 追问缺失内容 → 用户审阅确认 → 原子发布 → 展示定义与执行条件

## 线框

```text
行动 [草稿 / 已确认]
  检验来料批次 · 待澄清
  对象：来料批次  输入：待检批次  输出：检验结果
  状态：待检 → 已检  约束：验收规范（待澄清）
  [补充信息] [审阅并确认]（缺项时禁用）
  已确认：定义完整 · 执行条件尚未校验
```

## 状态与反馈

空态给出下一步访谈建议；读取中显示局部加载；保存中禁止重复提交同一操作；成功采用服务回执刷新；失败保留编辑内容并定位字段；revision 冲突提示“内容已更新，请重新查看后确认”。重开项目显示持久化结果，不能凭记忆摘要伪造已保存状态。

业务角色和具体人员实例区分；标准文档和可执行规则区分；正文面向业务用户，不输出思维循环。技术 ID 仅详情用于诊断。编辑入口自动定位到对应区域。

## 可访问性与布局

图谱提供同内容列表和文本关系，颜色不是唯一分类标识；键盘可聚焦筛选、编辑和确认。桌面双栏，窄窗口切换访谈/模型面板，不产生水平裁切。输入框、弹层、图例和错误提示同时覆盖 light/dark 主题，采用项目主题 token。沿用 Epic 1 的 visual-design-specification.md，新增确认步骤遵循现有 shadcn/ui 对话框约定。
