# 交互设计 - Story P2.8

**Story:** Workflow 设计与解决方案执行契约发布  
**版本:** 1.0  
**最后更新:** 2026-07-28

## 设计目标

让用户在解决方案设计窗体内完成建模、门控检查和契约发布，并清楚看到哪些设计缺口阻止运行。运行时界面不出现 Workflow 编辑能力。

## 主流程

```text
打开解决方案版本
  -> 编辑 Workflow/Team、Agent、Skill、I/O 和策略
  -> 运行设计检查
  -> 查看并修复 DesignGap
  -> 确认方案版本
  -> 发布执行契约
  -> 显示 contractId、version、hash 和发布状态
```

## 界面区域

### 设计画布

- 复用 P2.7 的 Workflow/Team 视图。
- 节点展示 Agent、Skill、输入、输出和 verifier 摘要。
- 设计视图切换只改变建模和查看方式，不代表 runtime 模式。

### 发布检查面板

- 按拓扑、I/O、能力、验证、权限、预算和 HITL 分类展示检查结果。
- 每个问题可定位到对应节点或边。
- 存在阻断项时禁用发布按钮。

### 发布确认

- 显示 solution version、节点数、依赖数和策略摘要。
- 明确提示“发布后不可修改，调整需创建新版本”。
- 发布成功后显示只读 `contractId` 和缩短展示的 `contractHash`，支持复制。

## 状态

| 状态 | 界面行为 | 可用操作 |
|------|---------|---------|
| Draft | 可编辑设计 | 保存、检查 |
| Checking | 展示检查进度，防止重复提交 | 取消等待 |
| Invalid | 展示 DesignGap | 定位并修复 |
| Confirmed | 设计锁定，等待发布 | 发布契约 |
| Published | 只读展示契约信息 | 查看、创建新版本 |
| Revoked | 显示撤销原因 | 查看历史、创建新版本 |

## 错误反馈

- 拓扑错误：“方案存在未连接节点或非法依赖，请先修复。”
- I/O 错误：“节点输出与下游输入不兼容。”
- verifier 缺失：“该节点没有可执行验收规则，不能发布。”
- 版本冲突：“当前版本已发布，请创建新版本后修改。”
- 完整性错误：“执行契约校验失败，请重新发布新版本。”

所有错误保留技术详情入口，但默认显示可操作的业务描述。

## 可访问性与性能

- 检查结果使用文本和图标共同表达，不仅依赖颜色。
- 问题列表支持键盘导航，定位节点后焦点转移到目标。
- 发布按钮具备可读禁用原因。
- 大图谱检查在后台异步执行，UI 保持响应。
- 不在 UI 或 IPC 中传输大体积 artifact 正文。

## 运行时边界

多 Agent 运行界面仅显示绑定的方案版本、契约状态和执行进度。它可以提供“返回解决方案设计修复”的入口，但不得嵌入 Workflow 编辑器或运行时切换按钮。

## 2026-09-14：项目语义执行规划补充

设计时从访谈概念选对象，查看来源/确认状态，配置任务输入、产出、状态转换和审核；用具体业务对象预览。缺口定位到概念/来源/节点。用户不手填文件路径或hash；已发布版本只读，修改创建新版本。
