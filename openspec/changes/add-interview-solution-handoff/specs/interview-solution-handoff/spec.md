# Spec Delta

## Purpose

让用户在完成项目访谈后获得明确、可信且可操作的阶段反馈，并能从当前访谈会话直接进入同一项目的解决方案设计阶段。

## ADDED Requirements

### Requirement: 访谈完成必须由结构化项目事实判定

系统 MUST 根据当前项目已绑定的 canonical ontology、单据字段完整性和可信发布的业务行为定义判断访谈是否完成，不得仅通过模型回复中的关键词或自然语言承诺判定完成。

#### Scenario: 完整项目访谈

- **WHEN** 当前项目已有概念和关系，单据类概念不存在字段缺口，并且业务行为定义已通过可信确认发布
- **THEN** 系统将本次项目访谈显示为已完成

#### Scenario: 行为草稿尚未发布

- **WHEN** 当前项目只有概念和关系，或行为草稿仍待澄清、待审阅或待确认
- **THEN** 系统不得显示访谈已完成或提供阶段跳转建议

#### Scenario: 只有部分对象具备数据形态

- **WHEN** canonical ontology 已有 FactType，但仍有任一业务对象未被 FactType 覆盖
- **THEN** 系统明确列出缺少数据形态的对象，继续业务行为确认，不得结束访谈或推荐进入解决方案设计

#### Scenario: 行动或规则部分缺失

- **WHEN** 概念与关系已经形成，但可信发布的 Action 或 Rule 任一为空
- **THEN** 系统继续引导用户确认处理动作、状态变化、权限与业务规则，并提示完成右侧审稿确认

#### Scenario: 单据字段仍有缺口

- **WHEN** 当前项目仍存在未拆解到原子字段的单据类概念
- **THEN** 系统不得显示访谈已完成，并继续保留访谈补充入口

### Requirement: 会话区必须显示访谈收尾与下一阶段入口

系统 SHALL 在访谈达到完成条件后，在当前会话回复区末尾显示“访谈已完成”的收尾提示，说明业务模型已准备好，并推荐用户进入解决方案设计。

#### Scenario: 当前会话完成访谈

- **WHEN** 用户在当前访谈中确认最后一项业务行为并完成可信发布
- **THEN** 收尾提示立即出现在最后一条回复之后，并保持当前访谈窗口可继续查看

#### Scenario: 重新打开已完成访谈

- **WHEN** 用户重新打开一个已经满足完成条件的项目访谈
- **THEN** 系统根据持久化项目事实恢复并显示收尾提示，无需重新生成或修改历史消息

### Requirement: 用户可以进入同一项目的解决方案设计

系统 MUST 在收尾提示中提供“进入解决方案设计”操作，并将当前项目标识、项目名称和本体引用传给既有解决方案设计入口。

#### Scenario: 点击进入解决方案设计

- **WHEN** 用户点击收尾提示中的“进入解决方案设计”
- **THEN** 系统打开或聚焦当前项目的解决方案设计窗口，访谈窗口与历史内容保持不变
