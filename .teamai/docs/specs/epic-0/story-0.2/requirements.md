# 需求文档 - Story 0.2

**Story:** 0.2 - CUI 与核心调度层连接
**版本:** 1.0
**最后更新:** 2026-03-03

---

## 📋 需求概述

作为 OriginOS 用户，
我可以通过命令行界面（CUI）输入消息与 AI 对话，
系统通过核心调度层（pi-agent）处理我的意图并返回响应。

---

## 🎯 功能需求

### FR0.2.1: 消息提交

**描述:** CUI 可以将用户消息提交到核心调度层

**需求:**
- 支持通过输入框或命令行输入文本消息
- 支持提交请求到 pi-agent
- UI 立即显示用户消息已发送状态
- 显示"正在思考..."或类似处理状态

---

### FR0.2.2: 实时响应流

**描述:** UI 订阅核心调度层事件流，实时显示回复

**需求:**
- 订阅 pi-agent 的事件流（message_start, message_update, tool_execution_start 等）
- 实时显示 AI 生成的文本（流式）
- 显示当前执行的工具（工具名称和状态）
- 显示"正在思考..."状态当 AI 正在处理

---

### FR0.2.3: 消息历史管理

**描述:** 自动保存和显示对话历史

**需求:**
- 自动保存每次对话的用户消息和 AI 响应
- 在终端中显示完整的对话历史
- 支持新会话（清空当前历史）
- （Story 0.5 将实现持久化会话存储）

---

## ✅ 验收标准

### AC0.2.1: 消息提交功能

**Given** 用户在 CUI 输入消息
**When** 按下 Enter 或提供输入
**Then** 消息被提交到核心调度层
**And** UI 立即显示用户消息
**And** 显示"正在思考..."或类似状态

---

### AC0.2.2: 响应流显示

**Given** 核心调度层正在生成响应
**When** 事件流触发
**Then** UI 实时显示生成的文本

**具体事件:**
- `message_start` - 开始生成响应
- `message_update` - 文本更新（流式显示）
- `message_end` - 响应完成
- `tool_execution_start` - 开始执行工具
- `tool_execution_end` - 工具执行完成

---

### AC0.2.3: 工具执行显示

**Given** 核心调度层执行工具
**When** 事件流触发
**Then** UI 显示工具名称
**And** 显示工具执行状态

**示例输出:**
```
🔧 执行工具: read_file
   参数: {"path": "/path/to/file"}
✓ 工具完成
```

## 🔍 边界条件

### 正常场景

1. **用户发送文本消息**
   - 输入: "帮我创建一个项目结构"
   - 期望: 消息显示在终端，AI 开始处理，显示流式响应

2. **多轮对话**
   - 输入连续的多个消息
   - 期望: 可以继续对话，AI 保留上下文

3. **工具执行**
   - AI 调用工具（如 read_file）
   - 期望: 显示工具名称、参数和结果

### 异常场景

1. **空消息**
   - 输入: 空字符串或仅空格
   - 期望: 忽略提交或显示提示

2. **核心调度层错误**
   - AI 返回错误
   - 期望: 显示友好的错误消息

3. **超时**
   - 响应生成超时
   - 期望: 显示超时提示，允许重试

### 边界值

1. **长消息**
   - 输入超长文本
   - 期望: 可以处理（可能需要截断或分块）

2. **特殊字符**
   - 输入包含特殊字符或 Emoji
   - 期望: 可以正确处理和显示

## ⚡ 性能需求

### 响应时间

- **消息提交延迟:** < 50ms（从提交到发送至 pi-agent）
- **事件处理延迟:** < 20ms（从事件触发到 UI 更新）
- **流式更新延迟:** < 100ms（文本更新间隔）

### 资源使用

- **内存占用:** < 10MB（对话历史缓冲区）
- **CPU 使用:** < 5%（事件处理期间）

---

## 🔐 安全需求

### 输入验证

- 验证消息不超过最大长度限制（10000 字符）
- 过滤或转义终端转义字符
- 防止命令注入（消息内容不应被执行）

### 错误处理

- 捕获并显示 pi-agent 错误
- 防止未处理的异常导致 CUI 崩溃

---

## 📋 非功能需求

### 可维护性

- 代码结构清晰，易于理解和扩展
- 事件处理逻辑集中在合适的模块
- 提供清晰的错误日志

### 可扩展性

- 支持未来添加更多事件类型
- 支持未来添加图片消息
- 支持自定义输出格式

## 📊 数据结构

### 消息类型

```typescript
interface CUIMessage {
  type: 'user' | 'assistant' | 'system' | 'tool';
  content: string;
  timestamp: Date;
}

interface ToolEventMessage {
  type: 'tool_start' | 'tool_end';
  toolName: string;
  params?: unknown;
  result?: unknown;
}
```

### 状态类型

```typescript
interface CUIState {
  messages: CUIMessage[];
  isProcessing: boolean;
  currentTool?: string;
}
```
