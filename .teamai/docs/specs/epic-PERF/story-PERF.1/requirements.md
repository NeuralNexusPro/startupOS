# 需求文档 - Story PERF.1

**Story:** 桌面日志按日期滚动  
**版本:** 1.0  
**最后更新:** 2026-07-27

## 需求来源

当前 `packages/desktop/src/main/main.ts` 在启动时把日志路径固定为 `desktop.log` 和 `llm.log`，所有日期持续追加到同一文件。应用长时间运行或长期使用后，单文件不断增长，影响故障定位、文件查看和后续归档治理。

## 功能需求

### FR1 每日日志文件

- desktop 与 LLM 两类日志保持独立。
- 文件名分别为 `desktop-YYYY-MM-DD.log` 和 `llm-YYYY-MM-DD.log`。
- 日期使用运行设备的本地自然日；日志行时间戳继续使用现有 ISO 8601 格式。
- 文件必须位于 Electron `app.getPath('logs')`。

### FR2 跨日滚动

- 日志目标路径必须根据每次写入时的日期解析，不能只在应用启动时计算。
- 本地日期变化后的第一条日志写入新文件。
- 旧日期文件保持关闭写入状态，不重命名、不合并。

### FR3 追加与兼容

- 同一天多次启动必须以追加模式写入同一日期文件。
- 已存在的 `desktop.log` 和 `llm.log` 不删除、不改名、不合并。
- 本 Story 不实现历史日志压缩或自动删除，这些能力由 PERF.2 定义。

### FR4 行为保持

- 保留 `log`、`info`、`warn`、`error` 的级别映射。
- 保留 uncaught exception 与 unhandled rejection 的 desktop 日志。
- 保留现有 LLM 前缀过滤规则、序列化上限和日志正文。
- 日志写入失败不得影响原始 console 输出。

### FR5 可测试性

- 日期来源和日志目录必须可注入或由纯函数参数提供。
- 文件名解析与写入策略不得依赖真实系统午夜才能测试。
- 测试必须覆盖 Windows 和 POSIX 路径表现。

## 验收场景

### AC1 当日首次写入

**Given** 日志目录不存在且本地日期为 2026-07-27  
**When** desktop 和 LLM 各产生一条符合条件的日志  
**Then** 创建日志目录及 `desktop-2026-07-27.log`、`llm-2026-07-27.log`，内容分别写入对应文件。

### AC2 同日追加

**Given** 当日日志文件已有内容  
**When** 应用重启后继续记录日志  
**Then** 新日志追加在原内容之后，已有内容不被截断。

### AC3 不重启跨日

**Given** 应用在 2026-07-27 23:59:59 运行  
**When** 下一条日志发生于 2026-07-28 00:00:00  
**Then** 前一条位于 27 日文件，后一条位于 28 日文件。

### AC4 写入失败

**Given** 日志目录不可写或 append 操作失败  
**When** console 产生日志  
**Then** 原 console 方法仍被调用，应用继续运行，且失败处理不会递归调用被代理的 console。

### AC5 旧文件兼容

**Given** 日志目录存在旧版 `desktop.log` 和 `llm.log`  
**When** 新版本启动并产生日志  
**Then** 旧文件内容不变，新日志只进入带日期的文件。

### AC6 日期格式稳定

**Given** Windows、macOS 或 Linux 开发环境  
**When** 解析某个本地日期的日志文件名  
**Then** 文件名只包含 ASCII 字母、数字和连字符，不包含冒号、斜杠或时区文本。

## 边界与异常

- 系统时钟向前跨日时切换到新日期文件。
- 系统时钟向后调整到前一日期时，按当前本地日期追加对应文件，不覆盖内容。
- 日期切换与日志写入同时发生时，每条完整日志只能进入一个文件。
- 空日志不创建文件。
- 超长或复杂对象继续受现有 `util.inspect` 限制。
- 日志目录创建失败不能触发无限重试或递归日志。

## 依赖

- Electron `app.getPath('logs')`
- Node.js `path` 与 `fs`
- 现有 console capture 初始化顺序和 LLM 日志过滤规则

## 非功能需求

- 单次路径解析为常数时间，不扫描日志目录。
- 不增加网络调用或数据库。
- 不在日志中新增密钥、令牌、用户文件内容或其他敏感字段。
- 核心文件名与跨日逻辑单元测试分支覆盖率不低于 80%。
- console capture 集成点成功与失败路径覆盖率为 100%。
