## 🎨 交互设计概述

### 设计目标

为 OriginOS 的命令行界面（CUI）设计与 pi-agent 核心调度层无缝集成的交互体验。

### 设计原则

- ✅ **实时反馈** - 用户输入后立即看到响应
- ✅ **状态可见** - 随时了解 AI 处理状态
- ✅ **流程清晰** - 消息提交 → 处理 → 响应显示的完整流程
- ✅ **错误友好** - 清晰的错误提示和解决建议

---

## 📊 交互流程

```
用户输入消息
    ↓
[立即显示用户消息]
    ↓
[显示 "正在思考..." 状态]
    ↓
订阅事件流 → 实时更新:
    ├─ message_start → 清除 "正在思考..."
    ├─ message_update → 追加显示文本
    ├─ tool_execution_start → 显示工具执行
    ├─ tool_execution_end → 工具完成提示
    └─ message_end → 响应完成
```

---

## 🔑 关键交互元素

### 1. 消息输入

**显示:**
```
[originos] > 用户输入的消息...
```

**行为:**
- 用户输入后按 Enter 提交
- 提交后立即换行，在下一行显示用户消息
- 同时显示 `🤔 正在思考...` 状态

---

### 2. 状态指示

**正在思考:**
```
🤔 正在思考...
```

**工具执行:**
```
🔧 执行工具: read_file
   参数: {"path": "/path/to/file"}
✓ 工具完成
```

---

### 3. 响应显示

**流式文本:**
```
🤔 正在思考...

这里是我对您问题的理解...

[文本随事件流实时更新]
```

**示例完整交互:**
```
[originos] > 帮我创建项目结构

🤔 正在思考...

我将为您创建一个典型的项目结构...

🔧 执行工具: create_directory
   参数: {"path": "/project"}
✓ 工具完成

```
src/
├── lib/
├── tests/
└── README.md
```

项目结构已创建！
```

## 🎯 交互设计规范

### 颜色和样式

使用 ANSI 颜色代码增强可读性：

| 元素 | 颜色 | 用途 |
|------|------|------|
| 用户消息 | 绿色 (`\x1b[32m`) | 区分用户输入 |
| AI 响应 | 白色（默认） | AI 输出 |
| 状态指示 | 黄色 (`\x1b[33m`) | "正在思考..." |
| 工具执行 | 品红色 (`\x1b[35m`) | 工具名称 |
| 工具完成 | 绿色 (`\x1b[32m`) | "✓ 工具完成" |
| 错误消息 | 红色 (`\x1b[31m`) | 错误提示 |

---

### 动画效果

**流式文本:**
- 不添加光标闪烁（终端支持有限）
- 直接追加文本到当前行

**状态指示:**
- 状态出现时不清除历史（除非响应开始）
- 响应完成后清除状态指示

---

### 等待状态

**状态字符串:**
- `🤔 正在思考...` - AI 正在生成响应
- `🔧 执行工具: <tool名称>` - 工具执行中

**显示位置:**
- 状态显示在响应内容的开头
- 响应开始后，状态可以保留或清除（根据设计）

## 🔍 边界情况交互

### 空消息

**输入:**
```
[originos] >
```
（用户直接按 Enter）

**处理:**
- 忽略提交或显示提示
- 示例提示：`⚠️ 请输入消息内容`

---

### 超时

**场景:** AI 响应超时（例如 30 秒无响应）

**提示:**
```
⚠️ 响应超时，请重试
```

---

### 错误处理

**场景:** pi-agent 返回错误

**显示:**
```
❌ 错误: 无法处理您的请求
原因: [错误详情]

💡 建议: [可操作的建议]
```

---

## ♿ 可访问性设计

### 键盘导航

- Tab - 自动补全（未来功能）
- Enter - 提交消息
- Ctrl+C - 中断当前操作

### 屏幕阅读器支持

- 使用清晰的文本标签（如 `🤔 正在思考...`）
- 避免仅依赖颜色传达状态
