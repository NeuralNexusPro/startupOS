# OS.22 交互

## 用户流程

```text
OS 输入框 / 外部渠道消息
  → 立即确认已接收
  → 解析目标与会话
  → 显示等待/流式回复/工具状态
  → 必要时请求 HITL
  → 完成、取消或可恢复错误
```

普通 Agent、RoleAgent、Project Agent 与 Skill 的回复表现保持一致。项目 Multi-Agent 场景只展示项目级编排状态和用户可见聚合结果，不向渠道泄露内部 Agent 私有思考；允许展示脱敏的阶段信息，例如“研究 Agent 正在收集资料”。

## 状态与提示

| 状态 | OS UI | 外部渠道 |
|---|---|---|
| accepted | 输入消息立即出现 | ACK 或简短“已接收”能力 |
| running | 流式文本、工具状态 | 按平台能力流式更新或节流合并 |
| hitl | 可操作确认卡片 | 安全操作链接/平台卡片；无能力则转系统通知 |
| completed | 固化最终消息 | 结束 stream 并记录 receipt |
| failed | 错误与重试 | 脱敏失败提示，不暴露内部异常 |
| cancelled | 标记已取消 | 可投递时告知已停止 |

## 会话体验

同一渠道会话与同一目标默认续接；用户可“开始新会话”。群聊按 conversation/thread 隔离。路由目标变化时创建新 Binding，禁止把旧目标上下文静默迁入新目标。

## 可访问性与响应式

本 Story 主要复用现有 UI；新增状态使用 `role=status/alert`，支持键盘取消与确认，颜色符合既有 Tailwind 语义且不作为唯一状态提示。外部渠道按各平台可访问能力降级。
