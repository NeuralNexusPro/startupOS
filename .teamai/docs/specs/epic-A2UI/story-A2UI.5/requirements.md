# 需求 - Story A2UI.5

**Story:** 安全治理、测试基线与可观测性
**Epic:** Epic A2UI
**最后更新:** Planning 阶段

---

## 用户故事

作为产品和工程团队，我希望 A2UI 卡片可验证、可降级、可测试、可观测，以便 Agent 生成 UI 时不会引入安全风险、性能风险或不可维护的渲染分支。

---

## 背景

A2UI 会让 Agent 输出直接影响前端 UI。若缺少治理，风险包括超大 payload 卡死消息流、ECharts option 注入脚本、未知组件导致空白、用户动作重复提交、不同客户端表现不一致等。

---

## 功能需求

### 范围

1. 安全限制：
   - 禁止 HTML、脚本、函数、远程组件、任意 CSS。
   - ECharts option 只允许 JSON 可序列化对象。
   - URL、图片、文件引用必须经过白名单或安全代理。
2. 数据限制：
   - 单卡片 payload 大小上限。
   - 表格行列上限。
   - 图表 series / data 点数上限。
   - 表单字段数量上限。
3. 降级策略：
   - `fallbackMarkdown` 必填。
   - schema 失败展示降级文本。
   - 开发模式可显示错误摘要，生产模式不暴露内部堆栈。
4. 测试基线：
   - schema 单元测试。
   - 恶意 payload 测试。
   - 卡片渲染快照测试。
   - Playwright 覆盖核心卡片在桌面/移动视口下不溢出。
5. 可观测性：
   - 记录 A2UI parse/validate/render/action 事件。
   - 指标包含成功率、失败原因、组件分布、payload 大小、交互转化。

### 非范围

- 不接入具体监控平台。
- 不实现自动修复 payload。
- 不做全量性能压测。
- 不实现客户端能力协商。

---

## 规划产物

| 产物 | 说明 |
|------|------|
| 安全清单 | 禁止项、允许项、需要清洗的字段 |
| 限额清单 | payload、表格、图表、表单、动作的上限 |
| 测试矩阵 | schema、渲染、交互、移动端、恶意输入 |
| 观测事件 | parse、validate、render、fallback、action、error |
| 发布门禁 | 新增卡片类型必须满足的文档、测试和 fallback 要求 |

---

## 验收标准

- [ ] A2UI 安全禁止项完整覆盖 HTML、脚本、函数、远程代码和任意 CSS。
- [ ] 每类卡片都有明确 payload 大小和数据量上限。
- [ ] 所有错误路径都有用户可见 fallback 和开发侧错误分类。
- [ ] 新增卡片类型的测试门禁已明确，包括 schema、渲染和响应式视口。
- [ ] 可观测事件字段能支撑定位"为什么没有渲染成卡片"。

---

## 后续实现建议

未来实现时，A2UI 校验应默认 fail closed：任何未知字段、未知组件、未知版本或危险字段都进入 fallback，而不是尝试猜测渲染。
