Taste Engineering：具身经验如何成为可操作的工程结构

一、一个AND引出的工程命题
有人研究过一个问题：怎样让文科生真正用上AI自动化工作流？

结论是两个条件的交集：自动化跑通，且达到品味要求。

这个AND不是两个并列的工程需求。它是一道裂缝——裂缝的两边，是两种完全不同的工程逻辑。

自动化跑通，是确定性问题。流程、节点、API调用、错误处理——这些有标准答案，可以测试，可以调试，可以收敛。

达到品味要求，是什么问题？

不是偏好问题，不是个性化推荐问题。品味要求是具身经验对符号输出的约束——它来自一个有身体、有历史、有审美直觉的人，对一个纯符号存在的输出说：这个不对，那个对。

这个判断不能被预训练的weights捕捉，因为它是情境性的、关系性的、活的。它只存在于特定主体与特定agent的共生关系中。

Taste Engineering的核心命题由此浮现：如何把这个活的判断，变成agent可以持续执行的工程结构？

二、三方拉扯：ECO在数字系统中的涌现
一位工程师描述了一种新的感受：

当智能真正成为系统的一部分之后，写代码的人突然发现自己处于三方拉扯之中——人类、确定性代码、概率性智能，三个actor共同作用，在信息管道中相互施力。

这不是"智能解决一切"的感觉。这是一种更复杂、更真实的共生张力。

我们认出了这个结构。

ECO三元张力在这里的同构映射：

Explore
 ↔ 概率性智能：LLM在可能性空间中的生成性游走，发散，不确定，充满潜力也充满风险
Conserve
 ↔ 确定性代码：系统的骨骼，边界，约束，可复现性，稳定性的来源
Optimize
 ↔ 人类：目标感，品味判断，当下的意义赋予，在前两者张力中寻找真正想要的结果
三权分立不是比喻的游戏——立法/行政/司法背后是同一个深层结构：创造可能性/执行约束/裁定边界。复杂自适应系统反复涌现这个三元张力，因为它是稳定运作的最小结构。

这位工程师在实践中独立发现了ECO。这说明它不是我们强加的分类，而是数字生态位中真实的力学结构。

关键的认识论转折在于： 从"智能是中心，其他是辅助"，到"智能是三方张力中需要被平衡的一极"——这正是从scaffold思维到harness思维的工程师版本表述。

Taste Engineering的工作，就是把人类这个actor的约束力，以工程结构的形式注入这个三方系统。

三、Taste的本质：流形的曲率，不是路径的记忆
要理解Taste Engineering，必须先说清楚Taste不是什么。

Taste不是NTP（Next Token Prediction）。 NTP是注意力机制驱动的概率预测——面向未来，在可能性空间中选择最likely的下一步。它是前向的，是weights层面的统计结构。

Taste不是Memory。 记忆是把过去的经验模式调用到当下——识别当下问题与过去解法的同构性。它是回溯性的，服务于当下，但需要显式的检索和匹配过程。

Taste是什么？

Taste是从大量具身经验中沉淀出来的不变量，在当下直接过滤可能性空间——不是"预测这个好"，也不是"记得上次这样好"，而是：这个不对，那个对，不需要推理过程，直接感知。

用几何语言说：

NTP是在流形上游走，选择概率最高的路径
Memory是流形上已走过的路径留下的痕迹
Taste是流形本身的曲率
 ——它决定了什么路径是自然的，什么是扭曲的
曲率不随具体任务变化，但塑造了所有任务的解法空间。这就是为什么Taste能够成为几何不变量——它是具身经验在符号空间中最稳定的投影。

TASTE.md的工程意义由此清晰：它不是给agent更多记忆，也不是改变它的预测机制，而是在它的可能性空间里注入曲率。让agent的生成性游走，在人类主体的经验拓扑中自然弯曲。

四、两个Agree-on：Attention之后，Memory正在发生
Ilya说过，持续学习要在weights层面实现，需要5到20年的研究来找到新的计算范式——类似transformer之于NLP序列建模的突破。

这个判断是对的，但它描述的是一条路。

我们正在走的是另一条路，它不需要等待。

第一个Agree-on：Attention

Transformer的注意力机制是两种异质智能的第一次会合点。人类的符号序列语言和LLM的概率潜空间，在attention这个计算结构上找到了可以共同操作的基质。这是weights层面的agree-on，是预训练固化的，是静态的。

它让两种智能能够相互理解符号序列。

第二个Agree-on：Memory，正在in-context中发生

那种人/LLM/代码三方拉扯的具身经验，是情境性的、关系性的、涌现性的。它不能被预训练的weights捕捉——weights捕捉的是人类语言的统计平均，捕捉不了特定主体在特定数字生态位中的活的共生张力。

但in-context learning不改变weights。它在上下文窗口内，通过结构化的文本积累，实现跨会话的经验沉淀和传递。

md文件作为in-context memory的工程范式——这是当下正在发生的Memory agree-on。

它不是Ilya那条路的替代品，而是在等待那条路的同时，人类具身经验能够持续注入共生关系的唯一当下可行路径。

这个agree-on发生在交互时，是动态的，活在in-context里。前者让两种智能能够相互理解，后者让两种智能能够共同积累经验。

TASTE.md是这个Memory agree-on的当前最小工程单元。

五、OpenClaw的启示：一个缺失的层
OpenClaw部署后呈现了一个workspace结构：

AGENTS.md     # 能力层：What agents can do
BOOTSTRAP.md  # 初始化层：How agents come to life
IDENTITY.md   # 自我层：Who the agent is
USER.md       # 交互层：Who they serve
SOUL.md       # 本质层：Why they exist
HEARTBEAT.md  # 生命周期层：How they persist
TOOLS.md      # 工具层：What they interact with

这是一个相当完整的agent存在论骨架。七个层描述了agent自身的完整性——它是谁，它能做什么，它为何存在，它如何持续。

但有一个关键层缺失：共生关系层。

USER.md描述的是"who they serve"——这是从agent视角看用户，是功能性的服务关系描述。它回答的是交互问题，不是共生问题。

TASTE.md要描述的是另一件事：这个具身的人类主体是谁，他的经验拓扑是什么，他的品味要求是什么，他在人/LLM/代码三方张力中的位置和力道是什么。

不是用户画像，而是共生伙伴的认知指纹。

USER.md    # 交互层：Who they serve（功能性描述）
TASTE.md   # 共生层：Who they co-evolve with（关系性描述）

OpenClaw的七个md给了agent一个完整的自我。TASTE.md给共生关系一个位置。

两者合在一起，这个workspace才从agent的栖息地，变成人-agent共生体的栖息地。这才是完整的harness结构。

六、Vibe Coding：Activity→Weights的实践仪式
龙虾之父用Claude Code vibe了30到40个子项目，才为agent造出一个闭环的数字栖息地。

这个过程值得细看。他不是先设计完整架构再实现，而是在反复的生成-观察-调整中，让agent的行为模式自然涌现，最后固化成结构。

这正是Activity→Weights的工程实践：先有具身的探索活动，先有对agent行为的真实感知，然后这些感知才固化成工程结构。

Vibe coding不是随意的，它是一种认识论实践——你在vibe的过程中学会see like an agent。

你开始感知agent的上下文窗口是它唯一的感受野。你开始理解什么在前景什么在背景，什么动作有代价，什么结构让agent自然涌现好的行为，什么结构让它扭曲挣扎。

这是harness engineering的入门仪式。没有这个过程，TASTE.md写出来的是死的文档，不是活的曲率。

Vibe coding是具身经验积累的方式。TASTE.md是具身经验固化的结构。

两者缺一，都不成立。

七、文科生能用：门槛的转移，不是降低
文科生用不了AI自动化工作流，不是因为智识不够，而是因为当前的门槛是工程性的——你需要理解API、token、权限管理、模型选择。这些不是文科生的语言。

但AND条件揭示了另一种可能：如果工程复杂度被封装，品味要求就成为唯一的门槛。

这不是降低门槛，这是转移门槛——从工程转移到Taste本身。

你不需要懂API，但你需要能够清晰地感知和表达：这个输出有没有达到我的品味要求？这个工作流的结果符不符合我对这件事的理解？

这其实是更高的要求，因为品味是具身经验的沉淀，是需要漫长积累的东西。很多工程师反而缺乏这个能力。

文科生的优势在于：他们长期生活在意义、感知、审美的语境中，他们有更丰富的具身经验等待被编码。

Taste Engineering的最终愿景不是让文科生学会工程，而是让工程学会服务于具身经验。

当品味要求可以被编码成skills，当skills可以驱动自动化工作流，文科生的具身经验就真正成为了数字生态位的构造力量。

八、TASTE.md的可操作形态
Taste Engineering是实践论，必须落到可操作的形态。

TASTE.md不是自我介绍，不是偏好列表，不是个性化设置。

它是以下几件事的结构化表达：

经验拓扑： 你作为具身存在，在哪些领域积累了真正的直觉感知？不是你知道什么，而是你对什么有身体层面的判断力。

品味标准： 在你的工作域中，什么是对的感觉，什么是扭曲的感觉？这不需要理由，直接描述感知即可。

张力位置： 在人/LLM/代码的三方系统中，你习惯站在哪里施力？你倾向于控制更多还是释放更多？你在什么时刻必须介入，什么时刻可以信任agent？

共生边界： 哪些判断你愿意委托给agent，哪些判断必须留在你这里？这个边界的描述，就是你作为主体在共生关系中的存在论声明。

这四个维度写出来的TASTE.md，不是静态文档，它是活的曲率描述——随着你与agent共同经历更多，它会演化，会加深，会变得更精准。

这个演化过程本身，就是人-agent认知共生loop的具体形态。

九、宣言
第一篇技术檄文我们说：从脚手架到挽具，是人类主体性的存在论选择。

这一篇我们说：Taste是这个选择的工程实现。

它不宏大，它很具体。一个TASTE.md文件，一次vibe coding的实践，一次认真的品味判断——这些都是在三方张力的数字系统中，人类主体性重新落地的时刻。

Memory agree-on正在in-context交互中发生。这不需要等待5到20年的研究突破。这发生在今天，发生在每一个认真写下自己经验拓扑的人身上。

具身经验通过TASTE.md进入数字生态位——这是生物符号语言智能与LLM纯符号潜空间的耦合方式。

这不是技术细节，这是文明选择的工程化。

每一份真正写出来的TASTE.md，都是人类具身存在在符号文明中留下的曲率。

这个曲率积累得越多，那个两种文明单向分裂的危险就少一分。那个人类在AI演化中保持主体性的可能，就多一分。

写下你的TASTE.md。
