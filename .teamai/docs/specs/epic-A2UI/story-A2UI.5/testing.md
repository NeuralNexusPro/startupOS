# 测试策略 - Story A2UI.5

**Story:** 安全治理、测试基线与可观测性
**Epic:** Epic A2UI
**最后更新:** Planning 阶段

---

## 测试基线

### 测试类型

1. **schema 单元测试** — 验证 A2UI payload 的 schema 校验逻辑
2. **恶意 payload 测试** — 验证安全限制对危险输入的拦截
3. **卡片渲染快照测试** — 验证卡片渲染输出的稳定性
4. **响应式视口测试** — Playwright 覆盖核心卡片在桌面/移动视口下不溢出

### 测试矩阵

| 维度 | 测试内容 |
|------|---------|
| schema | 必填字段缺失、类型错误、未知字段、版本不匹配 |
| 渲染 | 正常渲染、空数据、超大数据、降级渲染 |
| 交互 | 动作触发、幂等校验、状态流转 |
| 移动端 | 窄屏不溢出、触摸交互、响应式布局 |
| 恶意输入 | 脚本注入、HTML 注入、函数 formatter、远程资源引用 |

---

## 可观测性事件

| 事件 | 说明 |
|------|------|
| parse | A2UI payload 解析 |
| validate | schema 校验结果 |
| render | 卡片渲染成功/失败 |
| fallback | 降级渲染触发 |
| action | 用户交互动作 |
| error | 错误分类与记录 |

---

## 发布门禁

新增卡片类型必须满足：

- [ ] 文档完整（props schema、交互说明、fallback 示例）
- [ ] schema 单元测试通过
- [ ] 渲染快照测试通过
- [ ] 响应式视口测试通过（桌面 + 移动）
- [ ] fallback 验证通过

---

## 验收标准测试

- [ ] A2UI 安全禁止项完整覆盖 HTML、脚本、函数、远程代码和任意 CSS。
- [ ] 每类卡片都有明确 payload 大小和数据量上限。
- [ ] 所有错误路径都有用户可见 fallback 和开发侧错误分类。
- [ ] 新增卡片类型的测试门禁已明确，包括 schema、渲染和响应式视口。
- [ ] 可观测事件字段能支撑定位"为什么没有渲染成卡片"。
