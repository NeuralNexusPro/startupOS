# Spec Delta

## Purpose

让已完成概念和关系访谈、但尚未确认业务行为契约的项目，在重新打开时恢复到可理解且可继续完成的业务行为确认阶段。

## ADDED Requirements

### Requirement: 识别待完成的业务行为建模

系统 SHALL 在打开已绑定 canonical ontology 的项目访谈时，识别其中已有至少一个概念和一条关系、且没有已发布的事实类型、行动和规则的状态，并将其作为待完成的业务行为建模。

#### Scenario: 概念关系已发布但行为未确认

- **WHEN** 用户重新打开一个已有概念和关系、但事实类型、行动和规则均为空的项目访谈
- **THEN** 系统进入业务行为确认阶段，并以已有概念和关系作为后续澄清的上下文

#### Scenario: 已发布行为契约的项目

- **WHEN** 用户重新打开一个至少有事实类型、行动或规则的项目访谈
- **THEN** 系统不得将该项目误标为待完成的业务行为建模

### Requirement: 恢复阶段对用户可见且可继续

系统 MUST 在项目访谈界面展示业务行为确认阶段及其待确认范围，并在存在历史会话时发起一次不伪造用户输入的续接提示，使用户可以继续完成行动、输入输出、状态变化、规则和权限的确认。

#### Scenario: 带历史会话重新进入

- **WHEN** 用户重新打开带有历史消息的待完成项目访谈
- **THEN** 系统展示业务行为确认提示，并生成一条面向用户的续接说明，而不新增虚构的用户消息

### Requirement: 保持发布确认边界

系统 MUST 将恢复期间识别到的业务行为先保存为草稿；只有用户通过可信界面确认后才发布 FactType、Action、Rule、业务状态和流转到 canonical ontology。

#### Scenario: 未确认草稿

- **WHEN** 用户尚未确认业务行为草稿
- **THEN** 系统不得把自然语言描述或恢复提示当作已发布的可执行契约
